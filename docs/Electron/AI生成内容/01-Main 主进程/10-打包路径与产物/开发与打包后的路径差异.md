# app.isPackaged、resourcesPath、getAppPath 在开发和打包后为什么不一样？

## 考察点

- 开发态和安装包里的路径分裂
- 资源文件（图标、额外二进制）该放哪

## 参考答案

### 1. 三个值

```js
app.isPackaged;          // 开发 false，安装包 true
app.getAppPath();        // 开发是项目目录；打包后通常是 .../resources/app.asar
process.resourcesPath;   // 打包后才是 Resources 目录；开发时指向 Electron 自带的 resources
```

因此这种写法不可靠：

```js
// 开发能找到，打包后 __dirname 在 asar 里，相邻的 png 可能没进包
const icon = path.join(__dirname, '../assets/tray.png');
```

### 2. 推荐读资源的方式

业务脚本、页面、preload 跟着 asar 走，用 `app.getAppPath()` 或打包工具注入的路径。

要给操作系统看的文件（托盘图标、辅助 exe、`.node`）放到 `extraResources`，安装后出现在 `process.resourcesPath` 下面，而不是 asar 里：

```js
function resourcePath(...segments) {
  // 打包后从 Resources 读；开发时从项目 resources 目录读
  const root = app.isPackaged
    ? process.resourcesPath
    : path.join(__dirname, '../../resources');
  return path.join(root, ...segments);
}
```

electron-builder 示例：

```json
{
  "build": {
    "extraResources": [
      { "from": "resources/bin", "to": "bin" }
    ]
  }
}
```

### 3. 判断环境不要只看 NODE_ENV

打包机上也可能 `NODE_ENV=production` 但还在用 `electron .` 跑。区分“是不是安装包”用 `app.isPackaged`。

### 4. 常见故障

| 现象 | 原因 |
|------|------|
| 托盘图标开发有、安装后没有 | 图标没进 extraResources，或仍按项目相对路径读 |
| preload 找不到 | 路径写成了相对 cwd 的 `./preload.js` |
| 读到的是 Electron 默认资源 | 开发态误用 `process.resourcesPath` |

## 面试话术

> isPackaged 区分是不是安装包。getAppPath 在安装包里指向 app.asar，适合读业务代码。托盘图标和外部二进制要 extraResources，运行时从 resourcesPath 读。开发态的 resourcesPath 指向 Electron 自己的目录，所以读资源要分两条根路径。

## 常见追问

- **__dirname 在 asar 里还能用吗？** 能用来定位 asar 内的 js。不能用来定位必须被系统打开的二进制。
- **ESM 里没有 __dirname？** 用 `fileURLToPath(import.meta.url)` 自己算。主进程 ESM 和 preload 各自算，不要混用一个工具函数却忘了打包格式。
