# 浏览器缓存

## HTTP 缓存

强缓存和协商缓存是 HTTP 缓存的两种主要方式，它们可以通过设置 HTTP 响应头来实现。

### 强缓存

强缓存是通过设置响应头中的 `Cache-Control` 和 `Expires` 字段来实现的，告诉浏览器在多长时间内可以直接从本地缓存中获取资源，而不需要向服务器发送请求。

`Cache-Control` 常见取值：

- `public`：响应可以被任何缓存（包括客户端和代理服务器）缓存。
- `private`：响应只能被客户端缓存，而不被代理服务器缓存。
- `max-age=<seconds>`：缓存资源的最大有效期，单位为秒。
- `no-cache`：需要重新向服务器验证资源的有效性，但仍然可以使用缓存。
- `no-store`：不缓存该响应的任何部分。

`Expires` 指定资源的过期时间（HTTP 日期）。

```http
Cache-Control: max-age=3600
Expires: Wed, 23 Mar 2022 10:00:00 GMT
```

### 协商缓存

协商缓存是通过设置响应头中的 `ETag` 和 `Last-Modified` 字段来实现的。`ETag` 指定资源的标识符（通常是资源的哈希值），`Last-Modified` 指定资源的最后修改时间。

当浏览器再次请求资源时，会将上一次获取到的 `ETag`（通过 `If-None-Match` 请求头）或 `Last-Modified`（通过 `If-Modified-Since` 请求头）值发送给服务器，服务器根据这些值来判断资源是否发生了变化。如果资源未发生变化，则返回 304 Not Modified 响应。

```http
ETag: "686897696a7c876b7e"
Last-Modified: Wed, 23 Mar 2022 09:00:00 GMT
```

通过设置合适的缓存头，可以优化 Web 应用的性能，提高页面加载速度，并减少网络流量的消耗。
