# 常见问题与实用写法

本篇补充常用语法和工程问题；枚举、断言、工具类型等已有独立专题的内容，通过文末链接查阅。

## TypeScript 解决什么问题

TypeScript 用静态类型描述变量、函数和对象的约束，帮助编辑器提供补全、重构和错误提示，并在开发阶段发现类型不匹配。类型信息通常在编译后被擦除，外部数据仍需运行时校验。

## typeof、keyof 与索引访问类型

类型位置的 `typeof` 获取已有变量的类型；运行时的 `typeof value` 返回类型名称字符串。`keyof T` 获取对象类型的键，`T[K]` 获取键对应的值类型。

```ts
const config = { host: 'localhost', port: 8080 };

type Config = typeof config; // { host: string; port: number }
type ConfigKey = keyof Config; // 'host' | 'port'
type Port = Config['port']; // number

const answer = 42;
type Answer = typeof answer; // 42，而不是 number
```

`keyof` 的结果可能包含字符串、数字或 symbol。类型位置的 `typeof` 主要用于标识符或属性访问，不能直接对任意函数调用表达式取类型。

结合泛型，可以保证返回值与传入的键对应：

```ts
function getProperty<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}

const host = getProperty(config, 'host'); // string
const port = getProperty(config, 'port'); // number
// @ts-expect-error config 中没有 missing 属性
getProperty(config, 'missing');
```

## const、readonly 与 as const

- `const` 禁止重新绑定变量，但不禁止修改对象内部属性。
- `readonly` 在类型检查时禁止重新赋值对应属性，不会冻结运行时对象。
- `as const` 保留字面量类型，并将字面量中的对象属性标记为只读、数组推断为只读元组。

```ts
const user = { name: 'Alice' };
user.name = 'Tom'; // 可以修改属性

const settings: { readonly theme: string } = { theme: 'dark' };
// @ts-expect-error theme 是只读属性
settings.theme = 'light';

const modes = ['light', 'dark'] as const;
type Mode = (typeof modes)[number]; // 'light' | 'dark'
```

这些约束不同于 `Object.freeze()` 的运行时冻结；`as const` 也不能保证外部引用指向的对象深层不可变。

## 常见符号

- `?.`：可选链，接收者为 `null` 或 `undefined` 时返回 `undefined`。
- `??`：空值合并，仅在左侧为 `null` 或 `undefined` 时使用默认值，保留 `0`、`false` 和空字符串。
- `!`：表达式后表示非空断言；表达式前则是 JavaScript 的逻辑取反。
- `value!.name`：非空断言后访问属性，由 `!` 和 `.` 组合，并非独立操作符。
- `field!: Type`：类字段的确定赋值断言，表示开发者保证它会被初始化。
- `_`：普通标识符，常用于表示未使用的参数，不是通配符。
- `**`：JavaScript 的幂运算符，例如 `2 ** 3` 为 `8`。

```ts
function label(value: { name?: string } | null): string {
  return value?.name ?? 'Anonymous';
}
```

非空断言和确定赋值断言不会执行检查或初始化，使用前需要有实际保证。

## 类型兼容性如何判断

TypeScript 主要采用结构类型：源类型满足目标类型要求的成员及其类型，即可赋值，不要求显式继承。

```ts
interface Named {
  name: string;
}

const person = { name: 'Alice', age: 24 };
const named: Named = person; // 源对象可包含额外属性

// @ts-expect-error 直接赋值的对象字面量会进行额外属性检查
const literal: Named = { name: 'Alice', age: 24 };

type Callback = (value: string, index: number) => void;
const callback: Callback = value => console.log(value); // 可忽略多余参数
```

函数参数名称不影响兼容性，函数可以忽略调用方提供的参数；参数类型和返回值仍需满足兼容规则。具体方向和 `strictFunctionTypes` 的影响见 [函数类型兼容](./10.协变与逆变.md)。

## 模块如何加载

TypeScript 根据 `moduleResolution` 等选项查找模块与类型声明，根据 `module` 等选项决定导入、导出的输出形式。最终的 JavaScript 模块由浏览器、Node.js 或打包器加载。

因此，类型检查通过并不保证模块能在运行时找到；例如 `paths` 主要帮助类型解析，不会自动改写输出代码中的导入路径，运行环境或打包器也需要支持相应别名。

## 定时器类型如何写

浏览器和 Node.js 的定时器返回类型不同，用 `ReturnType` 可以跟随当前项目中的函数声明：

```ts
const timeoutId: ReturnType<typeof setTimeout> = setTimeout(() => {}, 1000);
const intervalId: ReturnType<typeof setInterval> = setInterval(() => {}, 1000);

clearTimeout(timeoutId);
clearInterval(intervalId);
```

纯浏览器代码也可显式使用 `window.setTimeout`、`window.setInterval`。混合环境中，应保证创建和清理定时器使用同一套 API。
