# object、Object 与空对象类型

以下说明以开启 `strictNullChecks` 为前提：`object` 表示非原始值；`Object` 和 `{}` 都能接收大多数非空值，包括原始值，但不描述业务属性。

## object：非原始值

普通对象、数组、函数等可以赋给 `object`；`string`、`number`、`boolean`、`bigint`、`symbol`、`null` 和 `undefined` 不可以。

```ts
let value: object;
value = { name: 'Alice' };
value = [];
value = () => {};

// @ts-expect-error 原始值不能赋给 object
value = 'hello';
// @ts-expect-error object 没有声明 name 属性
value.name;
```

适用于只要求“这是一个对象”、无需访问具体属性的场景。它并不是原始类型。

## Object：宽泛的全局对象接口

`Object` 是标准库中的接口，描述 `toString` 等通用成员。原始值也可满足这个接口，因此它不能用于排除原始值。

```ts
let globalObject: Object;
globalObject = { name: 'Alice' };
globalObject = 'hello';
globalObject = 12;
globalObject.toString();

// @ts-expect-error 严格空值检查下不接受 null
globalObject = null;
// @ts-expect-error Object 没有声明业务属性 name
globalObject.name;
```

`Object` 类型不同于运行时的 `Object` 构造函数，也不等同于小写的 `object`。业务代码通常应选择更具体的类型。

## {}：不声明属性要求的对象类型

`{}` 没有要求值必须包含某个属性，也没有要求值只能是空对象。在严格空值检查下，它可以接收除 `null`、`undefined` 外的值。

```ts
let nonNullValue: {};
nonNullValue = {};
nonNullValue = { name: 'Alice' };
nonNullValue = [];
nonNullValue = 12;
nonNullValue = 'hello';

// @ts-expect-error 严格空值检查下不接受 undefined
nonNullValue = undefined;
// @ts-expect-error {} 没有声明 name 属性
nonNullValue.name;
```

因此，`T extends {}` 约束的是非空值，不能用来保证 `T` 是普通对象。

## 如何选择

- 已知业务结构：使用接口或类型别名，如 `{ name: string; age?: number }`。
- 只要求非原始值：使用 `object`。
- 字符串键的字典：使用 `Record<string, unknown>`，读取值后再做类型检查。
- 尚不清楚输入类型：使用 `unknown`，它也可以接收 `null` 和 `undefined`。
- 没有可用属性的字符串键字典：可使用 `Record<string, never>`。

不要把 `Object`、`{}` 或 `unknown` 当作具体业务对象的类型。关闭 `strictNullChecks` 会放宽空值赋值检查，本文中的空值报错也不再成立。
