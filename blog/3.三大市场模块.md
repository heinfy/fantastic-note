## 一、定位（30 秒开场）

为 AI 应用开发三个扩展市场：**连接器**（MCP 工具）、**专家**（预设人设）、**技能**（Skill 包），每个都覆盖「浏览发现 → 详情 → 安装启用 → 我的管理 → 分享/创建」完整闭环。Vue 3 + TS + shadcn-vue，桌面（Electron）与 Web 双端复用。

## 二、架构分层

```
feature 页面（市场/详情/我的/分享/OAuth 回调）
    ↓
host 适配层（useDeepChatApplicationHost → 桌面 IPC / Web HTTP）
    ↓
shared contracts（zod DTO）+ shared business（client 封装）
```

三条设计主线：

- **双端一致性**：页面只调 `host.xxxClient`，零端判断，差异全下沉 host 层；
- **状态一致性**：写操作带 revision 乐观锁，防旧快照覆盖新数据；
- **列表一致性**：共享目录缓存 + Window 事件广播，多页面自动同步。

## 四、核心技术点

### 1. 一键安装启用 + revision 乐观锁

**一键** = `install`（幂等跳过）→ `setEnabled`（幂等跳过），用户点一次即「装完可用」。装完三步联动：更新 `sharedCatalog` 缓存 → 发 `*-marketplace:changed` 事件让其他页面刷新 → 桌面端刷新 MCP tools/prompts/resources 让工具即刻可被对话调用。

**乐观锁**：DTO 携带 `revision`，所有写请求带 `expectedRevision`，服务端 CAS 比对（等价 `UPDATE ... WHERE revision = ?`），不匹配即拒绝并自增。解决多窗口（市场/详情/我的）持旧快照并发写的脏覆盖问题。冲突处理：报错 → 用户刷新拿新 revision 重试，不自动重试（避免覆盖用户新意图）。类比 git：基于旧 commit push 被拒，先 pull 再改。

**双状态模型**：OAuth 连接器授权态归 Hub、安装态归本地 install projection，两者解耦；`mergeConnectorMutationResult` 对返回字段做 `??` 兜底，防接口未返回字段清掉本地值。

### 2. OAuth 授权（最核心亮点）

**方案**：客户端发起 `authorizeOAuth` → 系统/弹窗打开第三方授权页 → 回调落 Hub → 客户端每 2s 轮询 `getOAuthStatus`。回调页 `OAuthBindingResultPage` 只负责用户体验展示，**不承担状态传递**。

四个关键实现：

**① 预开弹窗防拦截**：`authorizeOAuth` 是异步请求，返回后再 `window.open` 会被浏览器用户激活过期拦截。解法：点击同步栈内先开空白窗占位，拿到 URL 后再导航。安全细节：`opener = null`（防 tab-nabbing）+ URL 协议白名单 `http/https`（防 `javascript:` 注入）。

**② 双端回调差异**（`resolveOAuthRedirect`）：桌面端 `openExternal` 唤起系统浏览器，无法回调本地 `file://`，回调落托管 Web 页 `/app/#/oauth/ok`；Web 端按 `BASE_URL` 拼「基础路径 + hash」，子路径部署也正确。

**③ 轮询三参数**：

- 2s 间隔——第三方回调客户端不可感知，只能问 Hub；
- 5min 总超时——防用户遗忘导致永久挂起；
- **6s 关闭宽限**——用户授权成功后立刻关回调页，服务端可能还没写完状态；一见 `closed` 就判失败会误伤成功授权，宽限期内继续查询。

**④ attemptId 全流程防竞态**：每个 await 后复查 `currentAttempt !== attemptId`，切连接器/路由切换/组件卸载（`onBeforeUnmount(stop)`）即作废旧流程，过期结果不会写进新页面；`finally` 里只有最新流程才有权清理窗口和状态。另外 focus/visibilitychange 时立即取消当前等待提前查询，减少切回延迟。`pendingConnectorId` 保证同时只有一个授权流程。

**绑定/解绑语义**：绑定 = 授权成功 + 创建 install projection；解绑 = 卸载投影 + `revokeOAuth` 撤销授权。

### 3. 技能包上传流水线

```
多来源输入 → 内存归档归一化 → 安全/规范校验 → 重打包 + SHA-256 → 按端分流安装
```

- **归一化**：拖拽文件夹（`webkitRelativePath` 还原结构）/ ZIP（fflate 解压）/ 单 md 提升为规范包。
- **安全**：`safeEntryPath` 拒绝 `..` / 绝对路径（防 zip 路径穿越）；保留目录条目尾 `/`（否则 fflate 重打包会把目录变空文件，解不出 `skill-name/SKILL.md`）。
- **校验**：文件 ≤2000、解压后 ≤20MB（逐文件累加提前中断）、`SKILL.md` ≤40KB、frontmatter `name` 必须等于根目录名（核心规范）；`description` 尽力解析失败不阻断。
- **指纹**：`zipSync(level: 6)` 规范化重打包 + `crypto.subtle` SHA-256。
- **分流**：桌面本地直装不走云端（支持本地目录路径直装）；Web 端 `uploadPackage → share → install` 三步，上传即创建云端定义 + 上传者投影，同时出现在「我创建的」和「我的技能」。

### 4. 全局状态同步

`createGlobalState` + `useConnectorMarketplaceCatalog`：跨页面共享一份列表，避免重复请求。并发控制三件套——`requestRevision` 丢弃过期响应、`activeRequest` 合并并发请求、Map 按 id 去重分页数据。写操作后 `notifyXxxChanged(source)` 广播，`source` 参数防自己刷新自己。

## 五、追问速答

| 追问                         | 回答要点                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| OAuth 为什么轮询不用回调？   | 第三方回调客户端拿不到控制权，结果只能落服务端；轮询 + 宽限期 + attemptId 解决竞态 |
| 乐观锁冲突怎么办？           | 报错提示 → 刷新拿最新 revision 手动重试，不自动重试避免覆盖新意图                  |
| 桌面/Web 如何复用？          | 业务在 feature + shared 层，host 适配层抹平 IPC/HTTP，页面零端判断                 |
| 上传为何重打包？             | 统一规范结构 + 产出稳定 SHA-256 供云端完整性校验                                   |
| 为什么目录条目要保留尾斜杠？ | fflate 会把无尾斜杠目录重编码为空文件，导致解包失败                                |

## 六、一句话收尾

> 三个市场的共性靠「乐观锁保状态、事件广播保列表、host 适配保双端」，个性难点是 OAuth 授权的弹窗/轮询/竞态三重问题和技能包的路径安全与规范校验——核心思路都是**把不可靠的外部过程（第三方授权、用户上传的包）收敛为可校验、可恢复的确定性流程**。
