## 一、模块定位

**问题**：Web 构建产物（dist）要传京东云 OSS，CDN 引用 `work-front/work/` 前缀。构建和上传拆两步会导致：产物漏传、版本与 CDN 不一致、CI 多维护一个 upload 脚本。

**方案**：写一个 Vite 构建插件，在构建生命周期内完成上传，`pnpm run build:web` 一条命令 = 编译 + 发布。核心文件 `scripts/vite-s3-upload-plugin.ts`（233 行）+ `test/main/viteS3UploadPlugin.test.ts`（229 行）。

export const createS3UploadPluginFromEnv = (env: S3UploadEnvironment = process.env): Plugin | undefined => {
  const resolvedEnv = { ...S3Object, ...env }; // 硬编码兜底，env 可覆盖
  const uploadKey = env.NODE_UPLOAD_KEY?.trim(); // CI 注入的 secret 优先级最高

  const options = resolveS3UploadOptions(resolvedEnv);

};

  const endpoint = value?.trim();
  if (!endpoint) return undefined;
  const candidate = /^[a-z][a-z\d+.-]*:\/\//i.test(endpoint) ? endpoint : `https://${endpoint}`;
  try {

## 三、关键设计点（附代码）

### 1. 时机：`writeBundle` + `order: 'post'` + `sequential: true`

```ts
export const createS3UploadPlugin = (options: S3UploadPluginOptions): Plugin => {
  return {
    name: 'joyagent-web-s3-upload',
    apply: 'build',
    configResolved(config) {
      config.logger.info(
        `[web-build:s3] Plugin registered: mode=${config.mode}, target=s3://${options.bucket}/${prefix}`
      );
    },
    writeBundle: {
      // 其它插件（Monaco worker、manifest）也在 writeBundle 写产物，
      // post + sequential 保证本插件读到的产物集是完整的
      order: 'post',
      sequential: true,
      async handler(outputOptions) {
        if (!outputOptions.dir) return this.error('S3 upload requires an output directory');
        const outputRoot = path.resolve(outputOptions.dir);
        const entries = await collectOutputFiles(outputRoot);
        // ...上传逻辑见下
      },
    },
  };
};
```

**话术**：默认 hook 是并发的，直接挂 `writeBundle` 会“包还没写全就开始传”；`order: 'post'` 排到最后，`sequential: true` 禁止 Rollup 并行优化该 hook，两者配合保证读到完整产物。

### 2. 文件收集：递归 + 排序 + 路径安全

```ts
const collectOutputFiles = async (directory: string): Promise<string[]> => {
  const files: string[] = [];
  for (const entry of await fs.readdir(directory, { withFileTypes: true })) {
    if (entry.name === '.DS_Store') continue; // 过滤系统文件
    const filePath = path.join(directory, entry.name);
    if (entry.isDirectory()) files.push(...(await collectOutputFiles(filePath)));
    else if (entry.isFile()) files.push(filePath);
  }
  return files.sort(); // 顺序确定，日志可对比
};

const normalizeObjectKey = (prefix: string, fileName: string): string => {
  const normalizedFileName = fileName.replaceAll('\\', '/').replace(/^\/+/, '');
  if (!normalizedFileName || normalizedFileName.split('/').some(part => part === '..')) {
    throw new Error(`Cannot upload unsafe Vite output path: ${fileName}`); // 防路径穿越
  }
  return `${prefix}${normalizedFileName}`;
};
```

### 3. 缓存策略：与 Vite 指纹对齐

```ts
const contentTypeFor = (fileName: string): string => {
  const extension = fileName.split('.').pop()?.toLowerCase();
  const contentTypes: Record<string, string> = {
    css: 'text/css; charset=utf-8',
    html: 'text/html; charset=utf-8',
    js: 'text/javascript; charset=utf-8',
    json: 'application/json; charset=utf-8',
    wasm: 'application/wasm',
    woff2: 'font/woff2',
    // ...
  };
  return contentTypes[extension ?? ''] ?? 'application/octet-stream';
};

const cacheControlFor = (fileName: string): string => {
  const normalizedFileName = fileName.replaceAll('\\', '/');
  // Vite 默认资源名含 8 位内容 hash；hash 变 = 文件变，可 immutable
  // 固定名文件（html/json/worker）必须 no-cache，否则发版不生效
  return /^assets\/[^/]+-[\w-]{8}\.(?!html?$|json$)[a-z0-9]+$/i.test(normalizedFileName)
    ? 'max-age=2592000,immutable'
    : 'no-cache';
};
```

### 4. 上传执行：`allSettled` 并发 + 完整性校验 fail-fast

```ts
const results = await Promise.allSettled(
  entries.map(async filePath => {
    const fileName = path.relative(outputRoot, filePath);
    const key = normalizeObjectKey(prefix, fileName);
    await client.send(
      new PutObjectCommand({
        Bucket: options.bucket,
        Key: key,
        Body: await fs.readFile(filePath),
        ContentType: contentTypeFor(fileName),
        CacheControl: cacheControlFor(fileName),
      })
    );
    return key;
  })
);

const failures = results.flatMap((result, index) =>
  result.status === 'rejected' ? [`${entries[index] ?? '(unknown)'}: ${String(result.reason)}`] : []
);
const totalCount = entries.length;
const successfulCount = totalCount - failures.length;

this.info(
  `[verify:web-build] S3 upload summary: total=${totalCount}, success=${successfulCount}, failed=${failures.length}`
);

if (failures.length > 0 || successfulCount !== totalCount) {
  this.error(`S3 upload failed: ${successfulCount}/${totalCount} artifacts uploaded; failures: ${failures.join('; ')}`);
}
```

**话术**：`allSettled` 不因单个失败中断其余上传，能拿到完整失败清单；汇总后校验 `success === total`，不等则 `this.error` 打断构建——“全量成功或 CI 红”，新 html 没发布，CDN 就永远引用不到半成品版本。

## 五、结果

- 发布链路从「构建脚本 + 独立上传脚本」收敛为**单一 Vite 配置**；预发/生产共用配置，差异全靠 env。
- 上传不完整即构建失败，杜绝“CDN 引用半成品版本”。

## 六、已知取舍与改进点（被追问时主动说）

1. **不是严格原子**：失败时部分对象已写入 OSS（无事务回滚）；兜底是“新 html 未发布”。可改为：先传全部 hash 资源、最后传 html 作为“提交点”。
2. **AccessKey/bucket/endpoint 硬编码在源码**（SecretKey 已移走 CI）——应一并移入 CI 变量。
3. **无并发上限**：可加 `p-limit`；无失败重试，可对网络错误做有限 retry。
4. **全量上传**：无增量比对，可按 ETag/size 跳过已存在对象。
