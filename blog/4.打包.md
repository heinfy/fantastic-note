## 一、一句话定位

把桌面端打包从「多个脚本 + 口头顺序 + 手拼环境变量」重构为**一个终端向导 + 一份可预览的执行计划**，核心原则是**配置与执行彻底分离**。

{/* truncate */}

## 二、要解决的问题（3 个痛点）

1. **入口分散**：`build:mac*` / `build:win*` / `sign:mac*` / `package:desktop` 多脚本并存，步骤顺序靠口头约定，产物不一致。
2. **环境易错**：直接 `pnpm run build` 会把 shell 遗留变量、`.env.local` 旧地址编进 main/preload/renderer 三个进程。
3. **副作用过早**：`build` 第一步就是 `clean:dist` + `ensure-runtime`——还没确定打什么包，dist 已被清、运行时已开下载。

## 三、总体设计：三层职责分离

```
用户输入（可能出错）→ 纯函数校验/生成计划（可测试）→ 执行器（唯一副作用点）
```

对应 4 个模块，各管一件事：

| 模块                           | 职责                              | 关键点                    |
| ------------------------------ | --------------------------------- | ------------------------- |
| `desktop-package-wizard.mjs`   | 交互收集 7 项参数                 | 纯问答，无任何副作用      |
| `desktop-package-plan.mjs`     | `createDesktopPackagePlan` 纯函数 | 校验 + 生成 steps/env     |
| `desktop-package-terminal.mjs` | Clack 封装 + 品牌化渲染           | 颜色/取消/任务日志        |
| `package-desktop.mjs`          | `printPlan` + `executePlan`       | 确认前不 spawn 任何子进程 |

## 四、核心流程（main 函数）

```text
解析 argv → （无 --yes/--dry-run 则进入向导）
        → createDesktopPackagePlan(options)   纯函数生成计划
        → printPlan(plan)                     打印配置摘要 + 每步命令 + 可复用命令
        → --dry-run 直接 return（不 spawn）
        → 交互模式弹「开始构建？」确认
        → executePlan(plan) 顺序执行
```

**7 步问答**：平台 → 环境(pre/prod) → 域名(默认/自定义) → 是否签名 → 是否公证(仅 macOS) → 架构(arm64/x64) → 运行时(安装/复用)。

## 五、关键实现细节（面试深挖点）

### 1. 计划是纯函数，天然可测

`createDesktopPackagePlan(input, hostPlatform)` 不碰终端、不碰网络：

- **白名单校验**所有参数：平台仅 `darwin/win32`、env 仅 `pre/prod`、签名仅 `none/sign/notarize`；
- **禁止交叉打包**：`options.platform !== hostPlatform` 直接 throw；
- **域名规范化**：`normalizeServiceOrigin` 拒绝带路径、查询参数、凭据的 origin（测试里有 `https://user:secret@example.com` 拒绝用例）；
- 返回 `{ options, env, steps }`，其中 steps 是**命令 + 参数数组**，不拼 shell 字符串，从源头防注入。

### 2. 环境变量由 plan 统一注入，不信任当前 shell

```js
env: {
  JOYAGENT_WORK_BUILD_ENV / RUNTIME_CHANNEL: 选定环境,
  JOYAGENT_WORK_SERVICE_ORIGIN: 选定域名,
  JOYAGENT_WORK_DESKTOP_DIRECT/CLOUD/CHANNEL_API_BASE_URL: 派生 API 地址,
  build_for_release: ''（清空，避免本地遗留值触发 notarize）,
  Windows 未签名时置空 CSC_LINK 等
}
```

`executePlan` 里 `{ ...process.env, ...plan.env }` **覆盖式合并**——向导选型压过 shell 遗留值，三个进程入口编进同一套配置。

### 3. 步骤顺序固化在 plan 里

mac：`build → 插件清理 → cua/feishu 插件 → (可选)原生运行时 + DuckDB VSS → electron-builder → 签名/公证`；win：签名走 VSIGN 校验前置 + electron-builder 后置验签。「该跑啥」的知识从 README/口头收进一个模块，可 review、可 diff。

### 4. 防误操作设计

- **无 `prepackage` hook**（测试断言），npm 生命周期不会自动 build；
- `--dry-run` 只算计划打印后 return；
- 非 TTY 环境跑交互直接报错提示「加 `--yes` 或 `--dry-run`」，不会挂死在 CI；
- `--yes` 支持部分参数（缺省有默认值：本机平台、`signing=none` 等）；
- 默认选项偏「安全」：环境默认高亮 PRE、签名默认否、运行时默认安装校验。

### 5. 执行器细节（体现工程成熟度）

- 每步独立计时、失败即停（`已停止后续步骤`），不继续跑错配置；
- pnpm 在 Windows 下经 `npm_execpath` 用 Node 直启，绕开 `.cmd` 需要 shell 的问题；
- `SIGINT` 转发给子进程并等待退出，Ctrl+C 不留孤儿进程；
- 自研 `taskLog`：子进程输出**原位重绘**（readline 光标控制 + `clearScreenDown`），按终端物理行数截断、resize 监听重绘，非 CJK 字符按 2 cell 保守计算宽度。

### 6. 交付闭环

执行完扫描 `dist/` 列出 dmg/zip/exe/yml/blockmap 及体积；`printPlan` 末尾输出**可复制的等价命令**（`pnpm run package -- --platform ... --yes`），实现「配置复现」。

## 六、测试策略

- **纯函数直测**：plan 生成（平台×架构×环境全组合）、参数校验拒绝、argv 解析；
- **执行器注入 mock runner**：验证 env 透传、失败中断后续步骤；
- **向导用 mock select/textInput**：断言 7 个问题顺序、mac/win 分支（win 不出公证问题）；
- **架构守卫测试**：断言 `package.json` 无 `prepackage`、旧脚本名已移除、plan 引用的 script 都存在——**用测试锁住架构决策**，防止入口再散回去。

## 七、面试叙事框架（30 秒版）

> 之前打包是多个脚本靠口头顺序，环境变量靠 shell 手拼，直接 build 还会先清 dist。我做了一个终端向导：Clack 分步收集 7 项参数，纯函数生成执行计划——计划里包含命令数组和要注入的环境变量——先打印完整 manifest 让用户确认，`--dry-run` 只看计划，`--yes` 供脚本调用。所有副作用排在确认之后，package 没有 prepackage hook，环境变量由计划统一覆盖注入，三个进程编进同一套配置。测试覆盖了计划生成、参数拒绝、执行中断和 script 收敛断言。

## 八、可能被追问的点（备好答案）

- **为什么不用 Inquirer？** 用的是 `@clack/prompts`，并在其上封装了品牌化渲染、取消语义（`PackageCancelledError` 统一退出）、任务日志原位重绘。
- **和 CI 怎么共存？** `build` 保持纯编译职责不变，CI 逐步调用不受影响；`package` 只是本地打包的统一入口。
- **量化收益？** 属 DevEx/防误操作改进：入口 1 个、步骤可预览可 diff、计划可 dry-run、配置可复现；且有架构守卫测试防回退。
- **为什么禁止交叉打包？** electron-builder 跨平台签名/插件产物不可靠，直接在 plan 层 throw，错误前置到执行前。

---

一个提醒：讲「默认环境」时别说错——`production` 构建未设变量默认是 **prod**；真正落 pre 的场景是 development/dev mode、遗留 `*_RUNTIME_CHANNEL=pre` 变量，或向导默认高亮 PRE 被直接回车。
