## 一、一句话总览

> 在 JoyAgent-Work 里搭建了一套 Web/Electron 双端行为埋点体系：**构建期注入 SDK → 统一路由识别 → 统一上报封装 → 关键链路全覆盖 → SDK 缺失自动降级**，支撑产品数据分析与运营复盘。

## 二、整体架构

```
Vite 插件(构建期注入) → pageId 路由映射 → 通用上报封装 → 领域事件封装 → 业务调用点
```

| 模块     | 文件                                                 | 职责                                        |
| -------- | ---------------------------------------------------- | ------------------------------------------- |
| SDK 注入 | `src/renderer/web/plugins/qidian-sdk-html-plugin.ts` | transformIndexHtml 按 marker + 环境变量注入 |
| 路由识别 | `src/renderer/src/lib/tracking/qidianPageId.ts`      | Hash 路由 → pageId 正则映射表               |
| 通用封装 | `src/renderer/src/lib/tracking/qidianTracking.ts`    | cls 拼接、公共维度、降级守卫、登录/打开事件 |
| 领域封装 | `skill / connector / expertQidianTracking.ts`        | payload 转换 + 语义化事件                   |
| 业务接入 | `useAgentrsAuth.ts`、聊天 Composer、市场页面         | 登录回跳、对话提问、市场转化动作            |
| 单测     | `test/renderer/lib/qidianSdkHtmlPlugin.test.ts` 等   | 注入 / pageId / 上报三层验证                |

## 三、核心实现

### 1. 构建期注入（Vite 插件）

```ts
// src/renderer/web/plugins/qidian-sdk-html-plugin.ts
const QIDIAN_SDK_MARKER = '<!-- QIDIAN_SDK -->';

// 内联 bootstrap：SDK 加载前挂好 window.__qd__ 配置
export const createQidianSdkBootstrapScript = (sid: string): string => {
  const routeRulesJson = serializeRouteRules(); // 构建期序列化路由规则表
  return `(function () {
  var win = window;
  function normalizePath(path) {
    var withoutQuery = (path || "/").split("?")[0].split("#")[0];
    var normalized = withoutQuery.replace(/\\/+$/, "") || "/";
    return normalized.charAt(0) === "/" ? normalized : "/" + normalized;
  }
  function resolveAppPath() {
    // Hash 路由优先，pathname 兜底
    var hashPath = (win.location.hash || "").replace(/^#/, "");
    if (hashPath) return normalizePath(hashPath);
    return normalizePath(win.location.pathname || "/");
  }
  function resolvePageId() {
    var path = resolveAppPath();
    var routeRules = ${routeRulesJson};
    for (var i = 0; i < routeRules.length; i += 1) {
      if (new RegExp(routeRules[i].test).test(path)) return routeRules[i].id;
    }
    return "unknown_page";
  }
  win.__qd__ || (win.__qd__ = {
    config: { sid: ${JSON.stringify(sid)}, pageId: resolvePageId } // 函数：每次上报时动态解析
  });
})();`;
};

// Vite 插件：transformIndexHtml 按 marker + 环境变量按需注入
export const createQidianSdkPlugin = (env: Record<string, string>, options: { enabled?: boolean } = {}): Plugin => ({
  name: 'joyagent-qidian-sdk',
  enforce: 'post',
  transformIndexHtml: {
    order: 'post',
    handler(html) {
      if (!html.includes(QIDIAN_SDK_MARKER)) return html;
      const enabled = options.enabled ?? env.VITE_QIDIAN_SDK_ENABLED !== 'false';
      if (!enabled) return html.replace(QIDIAN_SDK_MARKER, ''); // 关闭时只删 marker
      const sid = env.VITE_QIDIAN_SID?.trim() || DEFAULT_QIDIAN_SID;
      const sdkScript = `<script async name="qidian-sdk" crossorigin="anonymous" src="https://qdsdk.jd.com/qd.js"></script>`;
      return html
        .replace(QIDIAN_SDK_MARKER, '')
        .replace(
          /<head(\s[^>]*)?>/i,
          `$&\n    <script>${createQidianSdkBootstrapScript(sid)}</script>\n    ${sdkScript}`
        );
    },
  },
});
```

**双端接入**（一套插件，三个构建配置复用）：

```ts
// electron.vite.config.ts —— 测试模式禁用
createQidianSdkPlugin(env, { enabled: mode !== 'test' });
// vite.web.config.ts / vite.web.build.config.ts
createQidianSdkPlugin(env);
```

**设计要点**：

- **marker 驱动**：只有含 `<!-- QIDIAN_SDK -->` 的 HTML 入口才注入，无侵入。
- **按需可控**：`VITE_QIDIAN_SDK_ENABLED=false` 时只删 marker 不注脚本。
- **bootstrap 必须内联**：qd.js 是 async 加载的，`__qd__.config.pageId` 要在 SDK 执行前就位。
- **为什么构建期注入而非 npm 包/运行时注入**：无源码依赖、脚本进 HTML 首屏即生效、环境变量按环境开关、业务代码零改动。

### 2. Hash 路由识别（pageId 映射表）

```ts
// src/renderer/src/lib/tracking/qidianPageId.ts
// 规则表：具体路径在前、兜底在后
export const QIDIAN_PAGE_ROUTE_RULES: QidianPageRouteRule[] = [
  { test: /^\/$/, id: 'work_home' },
  { test: /^\/chat$/, id: 'work_chat' },
  // 技能上传必须先于技能详情（更具体优先）
  { test: /^\/plugins\/skills\/upload$/, id: 'plugins_skill_upload' },
  { test: /^\/plugins\/skills\/[^/]+$/, id: 'plugins_skill_detail' },
  { test: /^\/plugins\/skills$/, id: 'plugins_skills' },
  { test: /^\/plugins\/mcp$/, id: 'plugins_mcp' }, // 连接器
  { test: /^\/plugins\/experts\/[^/]+$/, id: 'plugins_expert_detail' },
  { test: /^\/plugins$/, id: 'plugins' },
  // ... automation / knowledge-base / settings 等
];

export function normalizeQidianAppPath(path: string): string {
  const withoutQuery = path.split('?')[0]?.split('#')[0] ?? '/'; // 去 query
  const normalized = withoutQuery.replace(/\/+$/, '') || '/'; // 去尾斜杠
  return normalized.startsWith('/') ? normalized : `/${normalized}`;
}

export function resolveQidianPageId(
  location: Pick<Location, 'hash' | 'pathname'> = window.location,
  rules = QIDIAN_PAGE_ROUTE_RULES
): string {
  const hashPath = location.hash.replace(/^#/, '');
  const path = hashPath ? normalizeQidianAppPath(hashPath) : normalizeQidianAppPath(location.pathname); // hash 优先
  for (const rule of rules) {
    if (rule.test.test(path)) return rule.id;
  }
  return 'unknown_page';
}
```

**设计要点**：

- 项目是 Vue **Hash 路由**，SPA 切页不刷新，SDK 默认读 pathname 会全部误报到首页 → **hash 优先、pathname 兜底**。
- **单一数据源**：同一份规则表，构建期序列化进 HTML bootstrap，运行时 `resolveQidianPageId` 复用，永不漂移。
- 未匹配返回 `unknown_page` 兜底，新增页面漏配不报错。

### 3. 通用上报封装

```ts
// src/renderer/src/lib/tracking/qidianTracking.ts
// SDK 守卫：未加载/未就绪 → undefined → 调用方静默跳过
function getQidianSdk(): QidianSdk | undefined {
  const qd = window.__qd__;
  if (!qd || typeof qd.click !== 'function') return undefined;
  return qd;
}

// 公共维度：每次上报自动带 pin + surfaceKind
function buildQidianTrackValues(values: QidianTrackValues = {}): QidianTrackValues {
  return {
    ...values,
    pin: getAgentrsPin(),
    surfaceKind: resolveCurrentApplicationSurface().surfaceKind, // desktop / desktop-web / web-agent
  };
}

// 底层入口：cls 约定 `模块|事件`；SDK 缺失静默丢弃，不影响主流程
export function reportClick(cls: string, values: QidianTrackValues = {}): void {
  const qd = getQidianSdk();
  if (!qd) return;
  qd.click({ cls, v: buildQidianTrackValues(values) });
}

// 按页面模块 + 事件名自动拼接 cls
export function trackClick(page: string, event: string, values = {}): void {
  reportClick(`${page}|${event}`, values);
}

// 自动解析当前 pageId 并上报（业务最常用入口）
export function trackCurrentPageClick(event: string, values = {}): void {
  trackClick(getCurrentQidianPageId(), event, values);
}
```

**设计要点**：

- **cls 约定 `模块|事件`**（如 `work_chat|useSkill`），业务不手写全名，数据侧可按前缀聚合。
- **公共维度自动注入**：`pin`（用户标识）+ `surfaceKind`（三种运行面），双端数据可直接分组分析。
- **降级策略**：SDK 判空静默 return，不抛错、不阻塞业务；埋点函数无返回值、不参与业务分支。

### 4. 领域事件封装（技能 / 连接器 / 专家，三者同构）

```ts
// src/renderer/src/lib/tracking/skillQidianTracking.ts（节选）
// 摘要 → 埋点 payload（转换函数独立，便于单测）
export function toSkillViewDetailTrackPayload(skill: SkillSummary) {
  return { id: skill.id, name: skill.name, origin: skill.origin, source: skill.source };
}

// 使用场景：缺字段不硬拼，只带实际有值的身份字段
export function toSkillUseTrackPayload(skill: SkillUseTrackInput): QidianTrackValues {
  const payload: QidianTrackValues = { name: skill.name };
  if (skill.id) payload.id = skill.id;
  if (skill.origin) payload.origin = skill.origin;
  if (skill.source) payload.source = skill.source;
  return payload;
}

// 语义化事件：业务只声明「做什么」，cls 拼接交给通用层
export function trackSkillInstall(skill: SkillSummary): void {
  trackCurrentPageClick('install', toSkillViewDetailTrackPayload(skill));
}
export function trackChatUseSkill(skill): void {
  trackCurrentPageClick('useSkill', toSkillUseTrackPayload(skill));
}
```

**设计要点**：领域层只做 **payload 转换 + 语义化事件命名**（`viewDetail / install / uninstall / start / use*`），`to*TrackPayload` 转换函数**缺字段不硬拼**，保证数据干净。

## 四、关键链路埋点

### 1. 登录回跳（最难点：SSO 整页跳转丢状态）

```ts
// src/renderer/src/lib/tracking/qidianTracking.ts
const PENDING_LOGIN_SUCCESS_KEY = 'joyagent.agentrs.pendingLoginSuccess';

// SSO 跳转前打标（sessionStorage 跨整页跳转存活）
export function markPendingLoginSuccess(env?: string): void {
  try {
    window.sessionStorage.setItem(PENDING_LOGIN_SUCCESS_KEY, JSON.stringify(env?.trim() ? { env: env.trim() } : {}));
  } catch {
    /* 隐私模式配额异常：忽略 */
  }
}

// 回跳后消费标记；返回 null 表示非登录回跳
export function consumePendingLoginSuccess(): { env?: string } | null {
  /* 读取 + remove，解析失败也清掉 */
}
```

```ts
// src/renderer/src/composables/useAgentrsAuth.ts
// 登录态确认成功后：
if (pin.value) {
  trackAppOpen(pin.value);
  // Web SSO 整页跳走，标记存活于 sessionStorage；returnUrl 回来在此消费
  const pendingLogin = consumePendingLoginSuccess();
  if (pendingLogin) trackLoginSuccess(pin.value, pendingLogin.env);
}

// 发起登录前先打标：
markPendingLoginSuccess();
const result = await authClient.login();
if (!result.success) clearPendingLoginSuccess(); // 失败/登出清标记，防止误报
```

**方案**：跳转前 `sessionStorage` 打标 → returnUrl 回来后 `checkStatus` 确认登录成功 → 消费标记上报 `loginSuccess`（带 env）；失败/登出清标记防误报。

let appOpenReported = false; // 模块级布尔：每个 renderer 会话只报一次

## 六、高频追问预备

1. **为什么构建期注入？** 无源码依赖，脚本进 HTML 首屏即生效，环境变量按环境开关，业务代码零改动。
2. **Hash 路由为什么特殊处理？** SDK 默认读 pathname，SPA hash 切页时 pathname 不变，会全部误报到首页。
3. **怎么保证不影响主流程？** SDK 判空静默跳过；sessionStorage 全部 try/catch（隐私模式配额异常）；埋点函数无返回值、不参与业务分支。
4. **双端怎么区分？** surfaceKind 公共维度（`desktop` / `desktop-web` / `web-agent`），数据侧直接分端分析。
5. **登录回跳怎么解决？** sessionStorage 打标 + 回跳后消费 + 失败清除，解决 SSO 整页跳转丢内存状态。
6. **和 SGM 的区别？** 奇点是**行为埋点**（click 转化分析）；SGM 是**性能监控**，另用独立 Vite 插件按 hostname 自动切 prod/pre 环境。

## 七、面试讲述主线
